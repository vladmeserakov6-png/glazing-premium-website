## Что проверить в браузере

1. Нажмите **Подобрать решение** в первом экране. Ответьте на три вопроса, вернитесь назад и измените ответ. Нажмите **В задание**: выбранный сценарий переносится в форму.
2. В каталоге нажмите **Сохранить** у нескольких решений. Откройте **Избранное и сравнение**. В таблице можно сопоставить до трех вариантов. При выборе четвертого снимите отметку с одного из предыдущих. Избранное хранится локально; удаление доступно в том же окне.
3. Нажмите **Включить избранное в задание**. В скачанном файле будет весь короткий список, а не только колонки текущей таблицы.
4. В блоке **Комфорт начинается изнутри** выберите стеклопакет, профиль или примыкание. Нажмите **Посмотреть по слоям**. Это поясняющая схема, а не инженерный чертеж конкретной системы.
5. Нажмите фотографию в галерее. Переключайте изображения стрелками, клавишами ←/→ или свайпом. Escape закрывает окно; фокус возвращается к кнопке открытия.
6. Заполните размеры и пожелания, закройте форму и откройте снова. Черновик сохраняется в текущей вкладке, включая перезагрузку. Кнопки **Скачать задание**, **Копировать текст**, **Текст задания** и **Очистить черновик** работают локально.
7. На телефоне используйте нижнюю панель подбора и избранного. Проверьте меню, возврат наверх и отсутствие перекрытия подвала.

## Данные и отправка

Персональные данные не запрашиваются. Ответы подбора и черновик используют `sessionStorage`; избранное — `localStorage`. Для блокировки хранилищ или переполненной квоты предусмотрена работа в памяти. В этом случае данные теряются после перезагрузки. Испорченные значения безопасно отбрасываются. Нет аналитики и внешних виджетов.

Получатель заявок и серверный сервис не настроены. Сайт не изображает отправку: результат можно скачать или скопировать и передать специалисту. Для реальных обращений нужны рабочий канал компании, подтвержденный получатель и согласованный процесс обработки. Секреты должны оставаться на сервере внешнего сервиса. GitHub Pages не выполняет серверные обработчики Next.js.

## Сборки

Обычный проект: `npm run dev`, либо `npm run build` и `npm run start`.

Статический предпросмотр для GitHub Pages:

```bash
npm run preview:export
npm run preview:check
npm run preview:serve
```

По умолчанию сборка рассчитана на `/glazing-premium-website/upgrade/`. Локальный адрес последней команды выводится в терминале; это адрес внутри машины, не публичная ссылка Codex.

Для другого адресного префикса передайте `NEXT_PUBLIC_BASE_PATH` и соответствующий полный `NEXT_PUBLIC_SITE_URL` в окружении команды. Используйте тот же префикс для проверки и сервера. Не ставьте завершающий слеш в переменных. Экспорт находится в `out/`, служебные файлы — в `.next/`. Для возврата к `npm run start` после экспорта заново выполните обычный `npm run build`.

Экспорт сам готовит WebP шириной 480, 768, 1200 и 1920 пикселей с ограничением исходного размера. Загрузчик Next/Image выбирает локальные файлы без CDN и серверного оптимизатора. Варианты генерируются при сборке и не хранятся в Git. Исходные изображения сохраняются. `.nojekyll` включается автоматически.

## Метаданные и поддержка

Настроены canonical, Open Graph и sitemap с адресом из конфигурации. `noindex` и запрет обхода остаются включенными, поскольку сайт использует рабочий бренд и не содержит утвержденных реквизитов. Снимать их следует при выпуске коммерческой версии. Нет вымышленных цен, рейтингов и бизнес-разметки.

Анимации построены на CSS и IntersectionObserver. Контент виден до выполнения JavaScript, `prefers-reduced-motion` отключает движение. Библиотека Motion удалена после замены единственного использования. Изображение первого экрана имеет приоритет загрузки.

Форма и ее библиотеки загружаются при открытии диалога. Заголовок окна остается на месте во время загрузки, предусмотрен клавиатурный цикл фокуса.

Для развития проекта сохраняйте Node из `.nvmrc`, используйте `npm ci` и обновляйте зависимости отдельными изменениями с проверкой сценариев. Дизайн-токены находятся в `globals.css` и `interactions.css`, справочные тексты — в `src/content/`, логика подбора и хранения отделена от компонентов.

SEO снижен из-за преднамеренного запрета индексации. Это один лабораторный замер: показатели публичного хостинга могут отличаться.

Автоматическая проверка доступности не заменяет работу со скринридером. Lighthouse в локальной среде — лабораторная оценка, а не полевые Core Web Vitals посетителей.

## Зависимости

`npm audit --omit=dev` не обнаружил уязвимостей. Полный аудит обнаружил одну проблему `braces` в цепочке инструментов ESLint, отмеченную как пять high-зависимостей. На момент проверки опубликованная версия `braces` — 3.0.3, исправленная версия недоступна. `npm audit fix --force` предлагает откат `eslint-config-next` до 14.2.35, несовместимый с текущим Next.js; такой откат не применялся. Пакеты этой цепочки не используются посетителями сайта. Отслеживать исправление upstream и затем обновить отдельным изменением.
